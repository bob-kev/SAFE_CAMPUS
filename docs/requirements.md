# SafeCampus - Requirements
## Functional Requirements
- **FR1.** System shall display a list of emergency types (Fire, Medical, Threat, Suspicious Activity, Accident, Harassment, Other).
- **FR2.** System shall allow one-tap calling of campus security/emergency number.
- **FR3.** System shall automatically detect and capture the user's GPS location.
- **FR4.** User shall be able to refine/edit their location on a map.
- **FR5.** System shall guide user through a structured report form.
- **FR6.** User shall review and confirm report before submission.
- **FR7.** System shall generate a report ID and show a confirmation screen.
- **FR8.** User shall be able to view report status after submission.
- **FR9.** System shall provide a "QuickTap" one-tap critical incident report.
- **FR10.** System shall provide a safety resources / help section.
## Mobile-Specific Usability Requirements
- **UR1.** All touch targets shall be at least 44px.
- **UR2.** Report flow shall be completable in ≤3 main taps.
- **UR3.** Font sizes shall remain readable on small screens (≥16sp body).
- **UR4.** High-contrast color scheme for visibility in all lighting.
- **UR5.** Primary action button must be prominent and consistently placed.
- **UR6.** Back navigation and cancel must always be available.
- **UR7.** System must confirm destructive actions.
- **UR8.** Loading/processing states must be visible to user.
## Non-Functional Requirements
- **NFR1.** Report data handled with privacy.
- **NFR2.** Interface responses within acceptable time.
- **NFR3.** Design language consistent across all screens.
